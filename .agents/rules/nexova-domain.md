# Nexova domain and placement rule

**Scope: Always active** for all coding agents working in this repository.

- Read root `BRIEFING.md` and the relevant memory-bank files before making changes. If business requirements conflict, stop and ask rather than infer.
- Product work must reflect Nexova's talent acquisition context. The active tracker scenario is the Executive Assistant search in Valencia.
- Preserve the shared API status and stage values. In user-facing UI, display only the human-readable labels specified by `BRIEFING.md`; never expose raw enum codes.
- Candidate notes are internal and may only be displayed in candidate detail views.
- Keep product artifacts in the established monorepo locations: public website in `uis/website/`, new internal apps in `uis/backoffice/` (existing tracker remains in `uis/talent-pipeline-tracker/`), and backend APIs/services in `services/`.
- Read the destination README before adding files. Do not invent parallel app or API folders.
- Update `memory-bank/progress.md` when implementation status, decisions, validation results, or next steps change.
